# SideNote 웹 체험 사이트

[English](README.md)

별도로 간략하게 구현한 리더가 아니라 **원본 SideNote 사이드패널 앱 전체**를
실행합니다. HTML·CSS·설정창·이벤트·노트 관리·에디터·이미지 뷰어/관리·휴지통·
가져오기/내보내기 코드를 그대로 복사합니다. HTML에서는 플랫폼 연결과 시작
스크립트 경로 두 곳만 바꿉니다.

처음에는 왼쪽 목록만 표시하며 오른쪽은 비워둡니다. 노트를 열면 같은 원본 앱을
오른쪽에서도 넓게 표시합니다. 내용과 설정은 양방향 동기화하며 모드와 스크롤은
독립적입니다. 목록으로 돌아가면 큰 화면을 비웁니다. 폭 760px 이하 또는 세로
화면에서는 왼쪽만 전체 화면으로 표시합니다.

설정·ESC 탐색·제목 편집·핀·길게 눌러 순서 변경·생성·삭제·복구·이미지 관리·
WYSIWYG/소스 편집·내보내기 메뉴는 모두 원본 처리입니다. 다운로드도 게시된
원본만 받는 방식이 아니라 방문자가 수정한 현재 내용을 내보냅니다.

## 웹 환경에서 달라지는 부분

두 화면은 메모리 IndexedDB와 `browser.storage.local` 호환 저장소를 공유합니다.
노트·이미지·설정·순서는 페이지 새로고침 시 초기화됩니다. 확장프로그램 데이터,
브라우저의 영구 IndexedDB 및 서버는 수정하지 않습니다. 보관할 수정본은
새로고침 전에 내보내세요.

일반 웹사이트에서는 브라우저 사이드패널 등록, 브라우저 전체 활성화 단축키,
확장 설치 이벤트/백그라운드 수명주기를 사용할 수 없습니다. 이것들은 흉내 내지
않습니다. 클립보드·다운로드·외부 이미지는 웹 권한·CORS·브라우저 지원을 따릅니다.

## 노트 게시

SideNote에서 내보낸 `.snote`를 `notes/`에 넣고 `notes/index.json`에 추가합니다.

```json
{ "id": "my-note", "file": "notes/my-note.snote", "pinned": false }
```

ID는 중복 없는 영문 소문자·숫자·하이픈, 파일명은 영문·숫자·밑줄·하이픈을
사용합니다. 제목과 개별 설정은 아카이브에서 읽으며 기존 JSON의 `title`은
무시합니다. 배열 순서는 초기 핀 순서와 수정 시각에 반영하고 이후에는 원본
SideNote 정렬을 따릅니다. 최초 목록 표시 전에 게시 아카이브 전체를 한 번
가져옵니다. 게시 파일과 첨부 이미지는 공개되지만 확장 내 개인 노트는 노출되지 않습니다.

## 개발과 배포

Windows의 Node.js 24에서 이 gh-pages 폴더를 기준으로 실행합니다.

```powershell
npm ci
npm run dev
npm run test:run
npm run build
```

http://127.0.0.1:4173 에서 확인합니다. 테스트는 실제 원본 앱 모듈과 메모리
호환 계층을 jsdom에서 실행합니다. build는 생성물 `dist/`만 교체합니다.
GitHub Pages는 `gh-pages / (root)`를 배포 대상으로 설정하고 커밋·push합니다.
확장 버전 태그와 사이트 배포는 별개입니다.

## 원본 전체 동기화

```powershell
npm run sync:sidenote -- C:\Users\justp\Documents\SideNote
npm run test:run
npm run build
```

원본 폴더에는 의존성이 설치되어 있어야 합니다(`npm ci`). 에디터와 확장을 빌드해
`build/chrome/` 전체로 생성 폴더 `app/`을 교체합니다. 시작 스크립트 경로 두 곳만
바꾸고 메모리 DB를 번들링합니다. 함수 일부를 추출하거나 별도 UI로 재작성하지
않습니다. PDF/HTML 내보내기 라이브러리까지 전부 복사하며 라이선스와 영문/한국어
WYSIWYG 문서도 갱신합니다. 원본 버전/커밋은 `vendor/sidenote-source.json`에 남깁니다.
게시 `.snote`는 수정하지 않습니다.

main 커밋마다 자동 push하는 것이 아니라 명령으로 동기화하는 방식입니다.
원본 진입점·상태 API·확장 API가 바뀌면 연결 계층도 검토하고 테스트한 뒤 함께
커밋하세요. `app/`은 직접 수정하지 않습니다.

구조: `app/`은 원본 배포물, `web-platform.js`는 메모리 호환 계층,
`app-bootstrap.js`는 게시 파일 초기화·원본 시작·화면 동기화,
`script.js`/HTML/CSS는 반응형 프레임 배치만 담당합니다.
